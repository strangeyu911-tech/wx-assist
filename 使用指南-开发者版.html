开发者版指南

路线 B：从源码运行和构建。适合想阅读代码、修改行为、参与开发的你。只想用起来 → 请看用户版指南（EXE 路线）。

Windows 10 / 11 Python 3.11+（3.13 实测） Node.js ≥ 18 Git

获取源码

git clone https://github.com/strangeyu911-tech/wx-assist.git
cd wx-assist
git checkout master

主分支是 master。本仓库是上游项目的 fork，持续跟进上游并附带自己的改进。

clone 之后缺什么

直接 clone 下来是跑不起来的——这是刻意的设计，不是缺陷。以下内容被排除在 git 之外，需要手动补齐：

缺失内容是什么缺了会怎样如何补齐
lib/ 微信数据库解密组件：6 个 DLL + lib/wasm/（25 个 WASM 文件）。闭源二进制，有合规风险，按惯例不入 git 致命 无法解密 / 读写微信数据库，读不到任何消息 从 Release 下载 wx-assist-lib.zip 解压到项目根（见下节）
models/ RAG 语义检索的嵌入模型 fast-bge-small-zh-v1.5（ONNX，约 91 MB） 降级 语义检索不可用，其余功能正常 可选，见 RAG 模型 一节
data/ 所有运行时数据（配置、SQLite、缓存、导出） 正常 空目录是预期状态，首次运行自动生成 不用管
.env 本地环境变量（API Key 等） 可选 也可以在界面里配置 复制 .env.example 为 .env 按需填写
为什么二进制不放进 git？

两个原因：工程上，git 会永久保存每个历史版本的二进制，仓库体积不可逆膨胀；Release 附件可随时替换、撤下。风险上，把「原创代码」和「来源不清的敏感二进制」物理分开：代码保持公开可审计，二进制只通过 Release 附件按需分发，不随 clone 扩散。

Python 环境与依赖

python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

实测通过的版本组合：Python 3.13 + 仓库锁定版本的依赖。requirements.txt 已包含全部后端依赖（含 QQ / 飞书绑定所需的 cryptography、微信解密所需的 pycryptodome、RAG 所需的 chromadb / fastembed 等）。

安装 lib 附件（必做一次）

这一步就是「安装完以后额外安装一次附件」

源码环境装好之后，还需要额外下载一次 lib 附件并解压到位——因为解密组件不在 git 仓库里。这一步只需做一次；组件版本不变的话，以后拉新代码也不用重做。

  1. 下载附件到 Releases 页面，下载最新版本 Assets 里的 wx-assist-lib.zip。
  2. 解压到项目根目录解压后应得到这样的结构（与 src/ 平级）：
wx-assist/
├── lib/
│   ├── wcdb_api.dll        # WCDB 接口层
│   ├── WCDB.dll            # 微信数据库引擎
│   ├── wx_key.dll          # 数据库密钥提取
│   ├── MSVCP140.dll / VCRUNTIME140.dll / VCRUNTIME140_1.dll   # MSVC 运行时
│   └── wasm/               # 图片解密 WASM 服务（25 个文件）
├── src/
├── ui/
└── desktop.py
附件从哪来？（备选方案）

lib 附件的原始来源是官方发布过的精简版 EXE（wx-assist_no_rag.exe）：两个 build spec 对 lib 的打包声明逐行一致，PyInstaller onefile 运行时会把 lib 解压到 %TEMP%\_MEIxxxxxx\。用 pyinstxtractor 解开归档即可取出 lib/——静态解包即可，无需运行来路不明的 EXE。正常情况下直接用 Release 里的 lib 附件就行，不必走这条备选路。

RAG 模型（可选）

想要 AI 对话的语义检索能力，需要补上嵌入模型（约 91 MB）。两种方式任选：

  • Release 附件：下载 models-bge-small-zh-v1.5.tar.gz，解压到项目根的 models/ 目录。
  • 官方源：从 Qdrant 官方 GCS 源获取 fast-bge-small-zh-v1.5.tar.gz（54.5 MB），解压为 models/fast-bge-small-zh-v1.5/。
别让 fastembed 自己联网拉模型

实测首次自动下载可能耗时 13 分钟，还会在用户目录另存一份 91 MB 的 HF 缓存副本。代码已优先使用本地 models/ 目录——只要目录在，就不会联网。不装模型也只是语义检索降级为不可用，程序照常运行。

前端构建

界面是 React + Vite 项目，位于 ui/。仓库不跟踪构建产物，源码路线需要自己构建一次：

cd ui
npm install
npm run build

构建产物输出到 ui/dist/，后端会直接伺服该目录（访问 http://127.0.0.1:17327）。改前端代码后重新 npm run build 刷新页面即可生效；开发时也可以 npm run dev 起 Vite 热更新服务。

运行

.venv\Scripts\python.exe desktop.py

启动后：Web 服务监听 127.0.0.1:17327，自动打开桌面窗口（pywebview / Edge WebView2；WebView2 不可用时自动退回浏览器）。首次使用前记得确认微信电脑版已登录，然后到界面里完成推送平台绑定与 AI 配置（流程见用户版指南）。

关键约定

• 端口 17327 硬编码在 src/web/server.py 的 start_web_server()。
• 不要同时运行源码版和 EXE 版：端口、iLink 会话、data 目录都会冲突。
• 桌面窗口内 F5 / Ctrl+R 可刷新（WebView2 默认不支持，程序已注入快捷键）。

构建 EXE

改完代码想打包成免安装的 EXE 分发？仓库提供两个 PyInstaller spec：

pip install pyinstaller

:: 完整版（含 RAG，产物 dist/wx-assist.exe，约 190 MB）
pyinstaller build_rag.spec --noconfirm

:: 精简版（不含 RAG，产物 dist/wx-assist_no_rag.exe，约 76 MB）
pyinstaller build.spec --noconfirm
要点说明
打包模式onefile：EXE() 直接接收 binaries/datas，没有 COLLECT 步骤。运行时自解压到 %TEMP%\_MEIxxxxxx\，退出时清理
frozen 路径desktop.py 检测 sys.frozen 后把项目根切到 EXE 所在目录，因此运行数据生成在 EXE 旁边，而不是临时目录
hiddenimports两个 spec 都维护了一份较长的动态导入清单——函数内 import 的模块（如 src.wechat.content_codec）、chromadb 的 Rust 绑定、飞书 SDK（lark_oapi）等静态分析检测不到，必须显式声明。新增动态导入的模块时记得同步补进去
excludes精简版额外排除 numpy / chromadb / fastembed / onnxruntime 等重依赖来压体积
lib 一致性两个 spec 的 lib/ 打包声明逐行一致；完整版多出的约 110 MB 全是 models/ 嵌入模型
前端依赖打包前确保 ui/dist 已按最新代码构建（spec 以 datas 形式整体打入）

架构速览

src/
├── bot.py               # 主循环：收发消息、事件分发
├── config.py            # load_config()：.env + 界面配置合并
├── web/                 # HTTP 服务（server.py 端口 17327）+ REST API + AI 对话
├── wechat/              # 微信数据层：WCDB 解密客户端、密钥提取、
│                        #   图片/语音/缓存解密、iLink 官方 Bot 收发
├── im/                  # 多平台推送框架：registry + 各平台插件
│   └── plugins/         #   wechat(iLink) / qqbot / feishu，各自含 onboarding 扫码绑定
├── assistant/           # 群摘要、关键词提醒、公众号监控、任务中心
│   └── rag/             #   语义检索：embedder + vector_store(ChromaDB) + reranker
├── agent/               # ReAct 引擎 + 工具注册表 + MCP Server
├── summarize/           # AI 后端抽象：deepseek / claude / stub，Prompt 管理
├── scheduler/           # Cron 定时调度
├── skill/               # 自定义 SKILL 扩展
├── mcp/                 # MCP 客户端与工具管理
├── db/                  # SQLite 存储 + 内容缓存
├── memory/              # 对话记忆整合
└── guard/               # 内容安全过滤

更完整的架构图见仓库 README.md 的「模块架构」一节；公开技术说明见 doc/ 目录。

日志与排错

线索位置典型用途
data/bot.log项目根 data 目录主要运行日志：绑定流程、推送投递、AI 调用、定时任务都在这里。排查一切「没反应」问题先看它
data/crash.log同上windowed 模式下的崩溃记录（EXE 闪退时看这里）
AI 设置 → 测试连接界面一键验证 AI 后端链路；「运行状态」页的 AI 状态在测试成功或首次成功调用后翻绿
端口冲突netstat -ano | findstr 17327确认是否有残留进程占用；找到 PID 后 taskkill 结束
WebView2 问题日志中出现 fallback 记录安装 Microsoft Edge WebView2 Runtime，或直接用浏览器访问 127.0.0.1:17327
改动验证小抄

改了后端代码 → 重启 desktop.py；改了前端 → npm run build 后刷新页面（不用重启后端）；改了绑定 / 推送逻辑 → 到「系统配置 → 推送平台」重新生成二维码实测，QQ 授权任务约 5 分钟过期属正常。
